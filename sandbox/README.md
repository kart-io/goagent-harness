# Sandbox execution

`Policy` carries file mode, canonical workspace, explicit writable roots and independent network policy. Zero mode/network normalize to read-only/deny; empty workspaces fail. Terminal workspace-root symlinks are rejected on every normalization, including when an existing root is renamed and replaced by a symlink. Initial ancestor aliases such as macOS /var are canonicalized; concurrent ancestor/mount replacement remains a documented path-validation race, so hosts should retain canonical policies and pin their resource ceilings. Context policies are copied and may change mode only when used by an adapter with a static policy; identity, approval and ceilings belong to the permissions controller. Never accept context policies directly from model arguments.

`FileSystem` retains the wrapped relative-path scope. Explicit configured extra roots are accessible through named relative scopes `@root1/path`, `@root2/path` in configuration order; arbitrary absolute host paths remain unavailable. Read-only writes return both ErrDenied and env.ErrReadOnly. Root and path checks are process-level checks; symlink replacement, renames and mount changes can race validation. They are not kernel isolation.

`Executor` supports:

* `docker`: explicit bind mounts, readonly workspace in read-only mode, `--network none` for deny. The container layer remains writable in every mode, preserving legacy semantics; it cannot write arbitrary host paths. Image must be supplied. Probe requires a POSIX shell and `/sys/class/net` for deny. Docker additionally applies a pinned Moby default seccomp profile with permissions removed for socketcall/socketpair/io_uring_setup and external socket creation: deny blocks socket creation entirely, inherit blocks AF_UNIX. Baseline syscall denials are retained; see profiles/README.md for source and license. Actual Docker 28.4 on Colima with the existing alpine:3.19 image passed workspace/extra-root writes, alias reads, readonly mounts, secret exclusion, nonzero status, namespace network deny, cancellation cleanup and mounted Unix stream and socketpair datagram denial. No image pulls were used.
* `native`: macOS sandbox-exec Seatbelt denies writes except configured roots and denies all network operations when requested. Confined network-inherit commands additionally deny outbound Unix pathname sockets while preserving ordinary TCP and anonymous socketpairs. Linux Bubblewrap binds a readonly host root, enables configured writable roots, uses a private PID namespace, and uses a network namespace for deny. Native workspace-write commands receive a fresh private temporary directory through TMPDIR, TMP and TEMP; Seatbelt allows that directory and Linux mounts a private tmpfs there. Cleanup removes the host directory. Read-only has no writable temporary directory and permits the /dev/null data sink. On Linux amd64/arm64 a seccomp filter additionally denies socket creation entirely for network deny, and AF_UNIX socket creation for confined network-inherit commands; io_uring_setup is denied to prevent bypassing the socket syscall. Linux confined commands also deny socketpair because a datagram endpoint could send to a host pathname socket. macOS instead blocks outbound Unix pathname sockets through Seatbelt and preserves anonymous socketpairs. Native Probe positively connects to a disposable host Unix-domain listener, then verifies a confined connection fails (including confined network-inherit). Other Linux architectures are unavailable for these policies. Windows native is unavailable.

  On Linux, `native` tries Bubblewrap first and falls back to Landlock when Bubblewrap fails the full probe, for example where unprivileged user namespaces are blocked. Set `Executor.Runner` to pin one; `Report.Runner` names the one in use. Landlock confines only a locked OS thread and starts the command from it, so the host process is unaffected and no helper binary is needed. It requires kernel ABI 3 (Linux 6.2) to govern truncate, and is otherwise unavailable. Below ABI 6 (Linux 6.12) it cannot block signals to processes outside the sandbox, so `Report.Enforcement` is `partial`; hosts needing an absolute boundary must reject that. Network policy uses the same seccomp filter as Bubblewrap instead of a network namespace. Landlock has no PID namespace: commands can see host processes (ptrace access such as /proc/PID/environ is denied), and descendants that call setsid outlive the command's cleanup while staying confined. Prefer Bubblewrap when both work, which is the default order.

  Verified on 2026-11-02 on kernel 7.0 (ABI 8) and as an ordinary user in an Ubuntu 24.04 container without Bubblewrap. Lower ABIs were not run: the `partial` path is covered only by the ABI comparison.

 Linux ARM64 Bubblewrap 0.9.0 was subsequently verified in the existing Ubuntu 24.04 Colima VM using a temporary extracted binary and a privileged test process: eight native/filter/runner groups passed ten consecutive rounds with no skips. Tests include outside writes, extra roots, private temp, /proc parent-root escape, Unix sockets and allowed TCP inheritance. The VM ordinary user could not configure the network namespace (RTM_NEWADDR: Operation not permitted), and Probe correctly returned ErrUnavailable. No system namespace/AppArmor configuration was changed. These results establish the tested privileged configuration, not ordinary-user support on every distribution. Linux amd64 is cross-compile checked only; startup/enforcement probes must pass on the deployment host.
* `local`: explicit danger-full-access plus network inherit only. It provides no isolation.

Every Run probes disposable directories before running the business command. Docker probes use the operator user cache directory under goagent-harness/probes so common VM daemons sharing the home directory can mount them; temporary children are removed. A daemon that cannot mount that cache path fails closed. Probe verifies backend startup, workspace writes, native outside writes (Docker absence of a sentinel that is positively created on the host, proving that specific outside host file is not visible), and network deny (native localhost TCP; Docker loopback-only interfaces). Failed probes return ErrUnavailable; there is no unrestricted fallback. macOS Seatbelt real workspace/outside/extra-root/subprocess/symlink write tests and localhost network deny pass on the development host. Internet endpoint reachability is not used as evidence because offline hosts produce false positives. The deny profile applies to all addresses; a separate live Internet test has not been performed.

Native commands and the Docker CLI inherit PATH, LANG, LC_ALL and TZ only, plus explicit EnvAllowlist names. Container commands preserve their image PATH and receive only explicit EnvAllowlist values. Docker HOME is /tmp unless explicitly overridden by an allowlisted HOME. Native private-temp values override allowlisted TMPDIR/TMP/TEMP for workspace-write. Environment filtering does not hide readable credential files. Native sandboxes share host resources and readable host files, and are unsuitable as a general untrusted tenant boundary.

Command cwd must be relative and resolve inside the workspace. Output is capped at 4 MiB. On Unix, commands use a fresh process group and the group is killed at completion/cancellation. macOS descendants that deliberately escape their process group (such as setsid) can outlive the command; Linux additionally uses a private PID namespace so its descendants die with that namespace. Native descendants retain OS file/network restrictions. Docker containers are forcibly removed at completion/cancellation. macOS process-lifetime containment remains incomplete.

Run tests with `env -u GOROOT GOWORK=off go test -race ./sandbox`. The `network: deny` probe needs `curl` on the host (or remote); without it `native` reports unavailable.

For a Linux host reached over SSH, see `sshsandbox`: a directory on the host is an instance, and each command runs through the installed `sandbox-runner` under the same native backend and probes.

Native tests skip with a reported unavailable reason when enforcement probes cannot run; this does not establish support for that platform.

Validation on 2026-11-01 exposed and fixed two errors: the HTTP probe used to send a response and close before reading the request, causing intermittent Linux curl EPIPE; probes now use a bounded HTTP server. A confined runner now acknowledges command startup before exec, so a backend failure cannot be mistaken for an ordinary nonzero command exit. The internal start marker is removed from returned output, and command arguments are passed through without shell interpolation. Sandbox contract v2 prevents recovery from silently mixing the previous execution contract.
