# Sandbox 后续执行路线图

状态：**调研后的实施提案，尚未执行**。2026-11-01。已交付功能以[当前API](../reference/SANDBOX_API.md)和[既有验收](../evaluation/2026-11-01-sandbox/REPORT.md)为准；新增依据见[能力调研](../research/2026-11-01-sandbox-capabilities.md)和[本轮探针](../evaluation/2026-11-01-sandbox-research/REPORT.md)。

目标仍是业务无关的 GoAgent 执行内核 + Harness 可替换资源装配。供应商控制能力留在独立模块，业务租户、持久资源台账和路由留在宿主。无需为沙盒再建立 Agent 循环。

P0/P1/P2表示依赖和优先级，不承诺尚未测量的人天或发布日期。每阶段先写失败用例，再实现和实际验证。研究分支可先合入文档，功能阶段需独立提交、审阅和验收。

## S0：立即可执行的契约修正

当前New接受TTL=30s，但真实Create返回422。这是本地校验与固定上游的已复现差距，不是后端支持短TTL。后续修复任务：

1. 把固定版本的最短创建TTL与秒数取整规则集中定义；小于60秒在New拒绝，默认10分钟保留。
2. 测试59秒拒绝、60秒接纳；验证非整数秒、24小时上限、服务端自定义上限。宿主不能从本地通过推导服务端一定接纳。
3. 保留实际服务的422回归与无分配证据，更新API参考；不借此放宽版本门禁。
4. 为宿主Resolver评估可选的context入口与兼容策略；测试回调迟到、Close超时和重试，不承诺强停不合作的Go回调。
5. 明确Isolated/Container/Network是能力声明；新增运行时证明先使用宿主报告或可选描述器，不把runc标成microVM。

## S1：持久资源与配额

### 资源记录模型（提案）

| 字段组 | 用途 |
| --- | --- |
| tenant_id、task_id、run_id、scope | 认证后的业务归属；不从模型文本取租户身份 |
| intent_id、attempt_id、generation | 调用前持久创建意图、去重与控制权代际 |
| provider/profile_version、image_digest | 稳定执行配置、可核对的部署声明 |
| sandbox_id、creation_token、observed_state | 已知实例与未知创建的对账线索 |
| owned/borrowed/retained、expires_at | 销毁责任与租约信息；借用不自动转成owned |
| quota_reserved、cleanup_state、last_error | 准入保留、清理重试和可审计结果 |

当前owner token在Provider内部生成，宿主事前并不知道。持久化设计必须解决创建标识的生成/注入时机，不能声称“捕获返回error再落库”覆盖了进程中途崩溃。第一步应明确可信Intent与供应商元数据的关联契约；不把模型参数变成幂等键。

建议状态：requested → allocating → ready → closing → deleted；未知响应进入uncertain，待对账后再转移。retained、borrowed应单独表达清理责任。状态机属于资源控制，不是新的业务工作流引擎。

验收必须覆盖：

- 同租户同task/scope并发Open只产生允许数量的实例；不同租户不能互相绑定ID。
- 创建超时、进程崩溃、清理失败、服务重启后能对账；空列表不是“从未分配”的证明。
- 配额在真正删除或明确转移责任后释放，不能在Close超时后提前释放并继续分配。
- 生命周期操作经可信控制服务检查generation；原始SDK的任意旁路调用不属于该fencing保证。
- TTL到期与任务关闭竞争、借用实例关闭、Retain后恢复，以及GC重复执行均不误删他人资源。
- 宿主退出先停止接收工作，再取消/排空，最后有限时清理；未完成资源进入台账供下次回收。

## S2：可选生命周期能力

以下仅为接口方向，**当前没有这些方法**：续期器、状态描述器、暂停/恢复器。避免把可选能力全部添加到Provider基础接口，强迫所有后端实现空操作。它们必须经过受管Session使用，不能直接绕过活动操作计数。

续期应使用绝对到期时间与宿主最大总存活期，避免网络重试无限累加。到期信息是可变租约，不应因每次续期变化而让稳定Manifest失效。任务结束、控制权丢失或Close开始时停止心跳。固定上游配置的创建timeout上限不等于续期总存活期上限，宿主需另行约束。[固定配置](https://github.com/opensandbox-group/OpenSandbox/blob/62a64f0b48cdd6b410f36e53c74dc7559c87719a/server/configuration.md)。

暂停前关闭新的操作准入并排空；排空期限到时不要假装已暂停。Pause/Resume/Close需要串行的控制门；未知响应保持受限状态并查询实际状态，不能自动Resume可能已被关闭或失去控制权的实例。Close仍保留owned/borrowed/Retain语义，Pause不能复用Destroy。

验收：命令运行中请求暂停、暂停后TTL到期、取消期间续期、Resume与Close竞争、服务重启后到期记录、旧控制者续期/删除被拒绝、从原实例恢复的Manifest稳定。当前原生SDK的成功探针只证明基础调用，不覆盖这些管理语义。

## S3：产物、批量FS和性能

产物清单建议包含相对路径、类型、字节数、SHA256、来源任务/实例、生成步骤及保留策略。总字节、文件数、单文件大小、解包后的路径和链接均有独立限制。先验证、后发布；错误产物不能成为下游成功结果。

批量接口可作为可选模块：批量stat/read、受限目录包上传、按版本写入和有界流式下载。必须保留：ContextResolver、最终保护路径、每文件条件写、路径no-follow、总量限制、取消后的未知状态和回收。

测量应覆盖真实仓库的read/edit/glob/grep与产物流转，统计RPC数、端到端时间、CPU/内存和错误。当前17字节小样本只说明往返开销值得优化，不证明某种架构已更快。不得通过把轮询无限调小、无界缓存或跳过持久化确认获得虚假的性能提升。

## S4：网络与凭证profile

网络profile由可信宿主选择，模型只能表达任务需求；不接受任意域名、内网CIDR或代理凭证直接扩权。父子Agent使用允许集合的交集；现有Network bool只能表示粗粒度上限，不能独自表达白名单。

最少场景：全拒绝、只读依赖镜像源、业务API白名单。测试DNS缓存、直连IP、IPv6、UDP、重定向目标、云元数据地址、跨沙盒通信、策略sidecar故障、规则热更新，以及域名与端口组合限制。只有真实验证后才能让当前Network=false通过装配。

服务端配置egress镜像不足以证明实例使用策略，必须核对请求与实际执行分支。凭证代理可单独接入，避免长期密钥写入客体环境；Vault、出站策略、吊销和日志脱敏需要联合验收。

## S5～S7：runtime、快照与其他供应商

强隔离：在具备条件的Linux/Kubernetes环境测runtime profile、实际挂载/权限、syscall兼容、PID/CPU/内存/磁盘行为。没有KVM或runsc实测不能用本地Docker结果替代。

快照：Docker文件系统commit与VM内存快照分别定义。创建新实例产生新ID和新Manifest；宿主若继续业务，应建立显式派生关系或新Run，不能绕过原执行身份核对。运行时、镜像、文件helper版本、网络profile和租约策略需一起验收。资源池需先证明独占租约和清理后无跨任务污染。

第二后端先复用Provider契约测试，核对创建失败、未知结果、中断确认、文件/CAS、变更保护、恢复和真实部署差异。供应商不支持的能力返回明确错误；不能用Remote=true或空实现冒充隔离、只读或条件写。

## 可观测性与发布要求

所有阶段记录tenant/task/scope/instance/command/intent身份与结果类别；密钥不入事件。建议事件包括creating、ready、operation_unknown、renew_failed、closing、cleanup_failed、deleted。若向业务发送webhook，用独立投递重试和稳定event_id，投递失败不重放已经执行的命令。

根模块和供应商子模块分别验证、发布；新增子模块API所依赖的根版本必须可获取。本地workspace通过不等于消费者可从模块代理下载。每次报告都写明真实验证环境、镜像digest、版本、未覆盖项和清理结果。
