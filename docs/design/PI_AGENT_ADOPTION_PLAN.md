# Pi Agent 设计采纳计划

状态：**调研提案，功能阶段未执行**。2026-11-01。依据[固定版本调研](../research/2026-11-01-pi-agent-design.md)及[230项验证](../evaluation/2026-11-01-pi-agent/REPORT.md)。不是兼容Pi API的承诺，也不要求引入TypeScript依赖。

目标：GoAgent继续提供通用执行、类型化workflow和持久语义；Harness提供装配、交互能力和执行环境组合；宿主负责租户、业务路由和资源治理。已存在的API优先补契约与案例，不因Pi有类似名字就重复实现。

## 阶段与归属

| 阶段 | 归属 | 依赖 | 交付（提案） | 主要验收 |
| --- | --- | --- | --- | --- |
| PI0 基线与对照 | 文档/验证 | 无 | 本轮已完成：固定Pi版本、两条运行路径、现有API映射 | 来源可复核；不把experimental包当成CLI已统一采用的能力 |
| PI1 事件、队列与结果契约 | 核心现有API的测试/文档，Harness案例 | PI0 | Steer/Followup/Redirect、完成事件、输出投影规范 | 输入不丢失/重复、事件顺序确定、未知结果不转成功 |
| PI2 上下文投影与压缩 | Harness及现有Builder扩展点 | PI1 | 持久历史、模型上下文、UI详情、压缩摘要的分层契约 | 工具配对、分支切换、压缩与插入输入竞争、恢复后投影一致 |
| PI3 会话分支产品层 | 宿主/可选会话服务 | PI1/PI2 | 复用session.Store.Fork，提供树形导航和身份关系 | 分支不伪造文件回滚；新Run和原Sandbox身份正确处理 |
| PI4 持久子Agent所有权 | 基于GoAgent durable的可选编排能力 | PI1，持久资源依赖Sandbox S1 | foreground/background、稳定child run/request身份、取消与等待 | 重启找回原child、父取消不留前台孤儿、后台显式转移责任 |
| PI5 远端协议与批量FS PoC | sandbox可选模块 | Sandbox S0/S1/S3 | 对比原生文件端点、批量RPC或受控长连接helper | 同环境、版本握手、背压、未知结果、CAS/路径保护与性能对照 |
| PI6 工具发现/Code Mode | 可选工具模块 | PI1/PI4/PI5的相关契约 | 延迟工具声明与受控组合，不替换固定workflow | 隐藏不等于授权；所有调用经过同一Dispatcher/预算/重放策略 |

Sandbox S0～S7见[既有路线图](SANDBOX_ROADMAP.md)。PI阶段不取代TTL对齐、持久资源台账和租户配额，不能先做会话UI再忽略资源恢复。

## PI1：先补清楚语义

GoAgent已有Handle.Steer、Inject、Followup、Redirect和Wait等能力。建立一张事件/输入状态表，把模型请求进行中、工具批次进行中、压缩进行中、结束处理、最终空闲和关闭区分开。

验收用真实受控Runnable/Dispatcher，不用仅检查事件名的镜像测试：

- 慢工具与快工具同批时，UI完成顺序和持久结果顺序分别有定义；保留并发与预算上限。
- assistant消息进入可观察状态后才执行相应工具前钩子；异步订阅者的失败/阻塞有明确边界。
- 输入在工具、压缩或结束钩子执行中到达，只消费一次；取消后未消费输入有明确归属。
- 普通message/turn结束不被入口误判为最终空闲；最终完成也不掩盖后台任务或未完成资源清理。
- ErrUnconfirmed优先于普通timeout；工具显示文本、结构化结果、UI详情和内部凭证各自声明可见性，脱敏覆盖所有暴露副本。
- 保持GoAgent当前参数校验/授权/替代调用检查，不照搬Pi可信钩子可修改参数后不重新校验的选择。

完成输出应是契约、回归和一组交互案例；只有发现现有扩展点表达不了的需求时才提议最小核心修改。

## PI2：模型上下文是投影

定义四类数据：原始持久条目、规范会话投影、单次模型请求、UI/审计详情。PreStep压缩改变后续模型上下文，但不应无声删除原始审计证据；UI详情不能因为便于存储就全部进入模型。

工具调用与结果应作为完整组处理；失败、取消、未知副作用与产物来源不得在摘要中消失。压缩记录需含来源范围、配置/模型身份与摘要版本；持久恢复重放已提交的决定，不能随机重算并替换旧执行事实。

验收包含：上下文预算边界、tool call/result跨切点、超长输出、分支后的摘要来源、连续压缩、压缩失败、摘要生成过程中Steer/Followup、以及已持久运行的确定性恢复。

## PI3：分支不是恢复外部世界

复用已有Store.Fork，不新增一个功能重复的核心Fork。产品层维护分支关系与显示标签，并把下列身份分开：

| 身份 | 负责内容 |
| --- | --- |
| Conversation/SessionID | 对话与分支历史 |
| RunID/ExecutionKey | 一次业务执行与副作用重放 |
| ChildRun/TaskID | 子工作所有权与等待关系 |
| SandboxID/Profile | 文件/命令所在的实际环境与权限 |
| Snapshot/Artifact来源 | 可选的环境派生或输入产物关系 |

在旧分支重新规划时，宿主应明确选择：只读取历史、在原环境继续、建立新执行，或从经过验证的产物/快照派生。不得因历史回到过去，就把当前磁盘、数据库或外部API也视为已回退。

验收同时检查对话投影与实际文件版本；再覆盖Git提交和一个可计数外部副作用，证明分支选择不会自动重放/撤销它。新沙盒不能通过省略ID绕过Manifest身份检查。

## PI4：持久子工作所有权

保留当前同步preset子Agent作为默认模式。持久子Agent另行定义稳定child run与提交身份，复用现有核心日志；不把父Run的全部journal随意交给子Agent，也不在Harness引入第二个持久执行循环。

前台子工作随父取消，父级完成条件包含前台子任务收敛。后台工作需要显式的所有者、租约、预算、可查询状态、结果投递和回收；不是无管理的goroutine。结果投递重试与子任务执行业务重放分开。

验收至少覆盖：

1. 创建child后、提交任务前崩溃；提交后、结果记录前崩溃；均找回同一child/request。
2. 父超时、用户取消、服务退出与子Agent正在执行工具竞争。
3. owned/borrowed/Retain的沙盒责任与child run一致，不把父级借用实例错误删除。
4. unsafe操作不因重启自动重跑；safe策略变更时拒绝旧记录与新策略不一致的重放。
5. 预算、网络和沙箱限制持续向后代收窄；没有workspace的中间层不丢失上限。
6. 后台child完成后，通知去重但不重新执行业务；控制权丢失时旧宿主不继续续期或销毁。

Pi Durable的owned Conversation可以作为契约参考，实验性API和Chord任务系统不直接移植。完成通知、等待上限和并发槽位的补充规则见[dsh-superagent采纳计划](DSH_SUPERAGENT_ADOPTION_PLAN.md)的SA2。

## PI5：让远端操作更少，而非更宽松

沿用当前Executor/FileSystem与同一Environment绑定。候选PoC比较：原生execd文件端点补语义、批量辅助操作、单会话受控文件服务。Rust不是必要选择，协议也不要求与Pi兼容。

借鉴hello/version/features、请求ID、二进制payload、句柄代际、分页/批量、背压、取消与连接未知结果。保留自己的Root限制、最终MutationProtector、合作写者CAS、原子替换/fsync和有界清理。Pi的cwd和Node式部分写语义不能代替这些契约。

验收用同一镜像、配额、文件集和真实任务比较现有基线，记录RPC数、P50/样本P95、内存、CPU和失败行为；网络断开、旧句柄重用、超限、链接变化与Close竞争必须一起测。没有真实daemon/协议PoC数据前不承诺性能提升。

## PI6：工具发现与组合

把“已注册/启用”“允许执行”“本次模型可见”分开。动态发现只改变声明或显式启用状态，不是授权凭据；嵌套工具仍经过Dispatcher和同一父级约束。

Code Mode如需实现，作为可选组合工具，必须有确定性/版本边界、嵌套调用身份、执行预算、输出限制和未知副作用处理。只开放经过授权的工具桥，不让脚本直接获得宿主文件、进程或SDK密钥。

固定业务流程继续用现有typed workflow。只有需要运行时工具组合的任务才评估脚本方式，不能因为Pi有Code Mode就把确定流程改成模型生成程序。

## 范围与发布

先完成PI1的现有契约对照，再选择PI2/PI3或Sandbox S0/S1/S3的独立阶段。持久子Agent与Code Mode属于较大功能，实施前应有独立规格和失败恢复测试。根模块、供应商子模块、宿主案例各自验证；本轮只新增调研与计划，不把这些提案列入现有API。
