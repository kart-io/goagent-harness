# Sandbox 能力与后续调研边界

本轮保留通用 Provider 生命周期与主线本机/容器隔离；没有远端供应商实现。先明确能力契约，再选择具体后端。已有能力见 [API](../reference/SANDBOX_API.md)，实施顺序见 [路线图](../design/SANDBOX_ROADMAP.md)。

| 能力 | 当前状态 | 后续需证明 |
| --- | --- | --- |
| 文件/网络策略与调用审批 | 主线 native/docker/local + Controller | 目标平台实际执行、拒绝与旁路行为 |
| 资源所有权与关闭 | Registry/Session 进程内管理 | 跨进程台账、租约、创建未知与孤儿回收 |
| 远端命令与文件系统 | 供应商无关接口 | 后端策略强制、路径/链接、条件写、取消、输出限制 |
| 快照与恢复 | 未实现通用产品功能 | 实例身份、文件/内存快照区别、版本与租约绑定 |
| 批量文件与产物传输 | 提案 | 字节/数量上限、hash、冲突和真实性能对照 |
| 会话持久子 Agent | Pi 调研，不是本轮实现 | durable 所有权、取消、去重、预算与恢复 |

能力布尔值是实现声明，不能当作独立安全证明。没有目标后端的真实证据前，不宣称 microVM、网络封锁、跨进程 CAS 或重启后自动恢复。保留 GoAgent 基础引擎与 Harness 资源装配的分层，业务租户、配额、路由和供应商凭据留在宿主。
