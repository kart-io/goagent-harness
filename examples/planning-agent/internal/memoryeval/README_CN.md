# 记忆布局评估

```sh
go run ./examples/planning-agent/cmd/memory-eval -dataset oracle.json -out plan
go run ./examples/planning-agent/cmd/memory-eval -dataset oracle.json -out smoke -backend scripted
```

在 harness 根目录运行以上命令。`-dataset` 读取本地 LongMemEval JSON，`-out` 指定新目录。默认离线生成清单，`scripted` 验证控制流，`live` 才连接宿主配置的服务。`-model` 指定形成和前台模型，`-judge-model` 可单独指定判分模型。只有独立判分请求收到参考答案。注入宿主客户端时，每次提交最多发送一个物理请求，须关闭客户端内部重试、请求拆分和重定向。CLI 已关闭 HTTP 重定向。

每个用例中的会话标识必须非空且唯一，非法输入在创建输出目录及模型调用前拒绝。每个用例每轮只抽取一次，复制前，宿主按固定用例时钟执行空查询，依框架现有排序选取最多八条有效记录并钉住，保留原始来源。该规则只依赖历史。可设 `-core-runes 0` 让新布局排除钉住记录。旧布局和新布局各读取一份独立的持久存储副本。关闭组从同一原始历史截取最近会话。三组使用相同字符上限、按 UTF-8 字节估算的 token 上限和输出上限，温度均为零。默认重复三轮。

清单在第一次模型调用前列出所有试验。结果逐题记录终态、答案、前台与判分费用，汇总中单列共享形成费用。保留的 JSON 字段 `physical_requests` 统计客户端提交次数，包含传输前本地失败，不是独立观测的网络请求数。取消时有界收集已缓冲的用量证据，不等待生产者关闭，运行仍返回取消错误。未提供账单时金额未知。成功率分母包含灌入失败、评分失败和未开始项。最终清单还按用例和轮次记录钉住数、成对比较题数及上下文变化数。所有成对上下文相同时记为 `no_layout_effect`。scripted 验证调用与账本，专项测试分别验证旧布局和新布局遗忘选中记录后的下一次物理请求。输出目录包含会话派生的记忆及模型答案，请使用合成或已授权的数据。
